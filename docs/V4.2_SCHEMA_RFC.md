# V4.2 Schema RFC — Spark Extensions

**Status:** Approved for V4.2 implementation (#353)  
**Date:** 2026-07-09  
**Policy:** Additive only — no column renames, no SPARK_LANES enum changes, no breaking `validate_spark()` defaults

---

## Purpose

Align spark rows with the cognitive spec (type, certainty, secondary domains, exposure class) while preserving V4.0 DB compatibility and all existing API consumers.

---

## New columns (sparks table)

| Column | Type | Default | Nullable | Enforced by |
|--------|------|---------|----------|-------------|
| `spark_type` | TEXT | `'observation'` | NOT NULL | `validate_spark()` when present in payload |
| `certainty` | TEXT | `'tentative'` | NOT NULL | `validate_spark()` |
| `secondary_lanes_json` | TEXT | `'[]'` | NOT NULL | JSON array of valid lanes |
| `exposure_class` | TEXT | `'public'` | NOT NULL | `validate_spark()` |

### Enum values

```python
SPARK_TYPES = frozenset({"fact", "decision", "intent", "observation"})
SPARK_CERTAINTIES = frozenset({"tentative", "exploratory", "confirmed"})
SPARK_EXPOSURE_CLASSES = frozenset({"public", "private"})
```

`SPARK_LANES` unchanged:

```python
SPARK_LANES = frozenset({
    "learning", "work", "relationships", "money", "health", "operating_style",
})
```

`SPARK_SENSITIVITIES` unchanged: `normal`, `sensitive`, `high`.

### Semantic mapping (spec → Crowley)

| Spec concept | Column | Notes |
|--------------|--------|-------|
| fact/decision/intent/observation | `spark_type` | New |
| tentative/exploratory/confirmed | `certainty` | Orthogonal to `trust_state` |
| active/inactive | `trust_state` | Keep candidate/active/stale/pinned/rejected |
| public/private/sensitive | `exposure_class` + `sensitivity` | private exposure often pairs with sensitive/high |
| secondary domain | `secondary_lanes_json` | Subset of SPARK_LANES |

## Domain aliases (not a column)

Module-level constant in `sparks.py`:

```python
DOMAIN_ALIASES: dict[str, str] = {
    "finance": "money",
    "financial": "money",
    "career": "work",
    "job": "work",
    "general": "operating_style",
}
```

Used at:

- Ingest normalization (`spark_extraction` post-parse)
- Query lane inference (`cognitive_query.py`, V4.3)
- Portable writeback lane normalization (extend existing bridge)

Invalid alias targets must still resolve to `SPARK_LANES`.

V4.3 lane inference may return multiple primary lanes for genuine cross-domain
queries. Single-domain queries should still filter tightly before scoring.

## Migration policy

### On `setup_spark_tables()` / `setup_db()`

Use idempotent `ALTER TABLE` guards (pattern already used elsewhere in crowley):

```sql
ALTER TABLE sparks ADD COLUMN spark_type TEXT NOT NULL DEFAULT 'observation';
ALTER TABLE sparks ADD COLUMN certainty TEXT NOT NULL DEFAULT 'tentative';
ALTER TABLE sparks ADD COLUMN secondary_lanes_json TEXT NOT NULL DEFAULT '[]';
ALTER TABLE sparks ADD COLUMN exposure_class TEXT NOT NULL DEFAULT 'public';
```

### Backfill rules

| Column | Existing rows |
|--------|---------------|
| `spark_type` | `'observation'` |
| `certainty` | `'tentative'` if `trust_state=candidate`, else `'confirmed'` optional heuristic in maintenance script only — default `'tentative'` for safety |
| `secondary_lanes_json` | `'[]'` |
| `exposure_class` | `'private'` if `sensitivity IN ('sensitive','high')`, else `'public'` |

Backfill runs once in migration helper; not required for tests using fresh DB.

### No migration

- Do not rename `lane` to `domain`
- Do not change `SPARK_LANES` values
- Do not alter `content_encrypted` behavior in V4.2 (V4.5 #372)

## Validation rules (`validate_spark()`)

When fields present in candidate dict:

1. `spark_type` must be in `SPARK_TYPES`
2. `certainty` must be in `SPARK_CERTAINTIES`
3. `exposure_class` must be in `SPARK_EXPOSURE_CLASSES`
4. `secondary_lanes_json` decoded list ⊆ `SPARK_LANES`, no duplicates, must not include primary `lane`
5. Omission of new fields → apply defaults before insert, not rejection

### Promotion interaction (V4.2 #355)

- Auto-promote to `trust_state=active` requires `certainty=confirmed` AND confidence ≥ threshold (e.g. 0.7)
- `certainty=tentative` never auto-promotes

## Extraction prompt changes

`spark_extraction.py` JSON schema adds optional keys:

```json
{
  "content": "...",
  "lane": "money",
  "why_keep": "...",
  "worth_reason": "...",
  "confidence": 0.85,
  "spark_type": "fact",
  "certainty": "confirmed",
  "secondary_lanes": ["work"]
}
```

Parser maps `secondary_lanes` → `secondary_lanes_json` string for storage.
