## Goal

Close the gap between **candidate** sparks (everything cognitive ingest creates today) and **cold-start exit** (which only counts `active` + `pinned`). Define deterministic promotion rules so confirmed, validated sparks become `active`; tentative/exploratory stay `candidate`. Align cold-start counting and add a read-time certainty precedence hook in retrieval — without rewriting the canonical score formula.

---

## Problem (current state)

| Area | Today |
|------|-------|
| `cognitive_ingest._assign_trust_state()` | Always `candidate` |
| `portable_writeback_sparks_bridge` | Always `candidate`; acceptance promotes **memory_items** only, not `sparks.trust_state` |
| `context_resolution.count_active_sparks()` | `active` + `pinned` only → threshold 10 |
| `context_orchestration` cold-start | Falls back to `memory_items` while candidates accumulate |
| `spark_retrieval` | Retrieves `candidate` sparks (only excludes `rejected`); no certainty weighting |
| Default `certainty` | `tentative` via `SPARK_CERTAINTY_DEFAULT` |

Cognitive ingest can produce dozens of retrieval-eligible candidate sparks while cold-start fallback remains permanently on.

---

## Design principles

1. **Code owns `trust_state`** — LLM never sets it (unchanged).
2. **Auto-promotion is conservative** — only `confirmed` + `normal` sensitivity + confidence gate.
3. **Manual paths are explicit** — seed/maintenance/acceptance can promote with audit metadata.
4. **No ranking rewrite** — certainty affects a read-time multiplier on the final score only.
5. **Stale/rejected lifecycle unchanged** — promotion is additive; T15/T16 paths stay intact.

```python
PROMOTION_MIN_CONFIDENCE = 0.65
AUTO_PROMOTE_CERTAINTIES = frozenset({"confirmed"})
MANUAL_PROMOTE_TRUST_FROM = frozenset({"candidate"})
```

### Eligibility

```python
@dataclass(frozen=True)
class PromotionDecision:
    eligible: bool
    reason: str  # confirmed_ok | tentative | exploratory | sensitive | low_confidence | wrong_state

def evaluate_promotion_eligibility(row: sqlite3.Row, *, manual: bool = False) -> PromotionDecision:
    """
    Auto: candidate + certainty=confirmed + sensitivity=normal
          + base_confidence >= PROMOTION_MIN_CONFIDENCE.
    Manual: candidate + sensitivity=normal + re-validate content security
            (certainty not required — operator/seed path).
    Never promote: sensitive/high, pinned, active, stale, rejected.
    """
```

```python
@dataclass(frozen=True)
```

## Certainty assignment at ingest (feeds promotion)

**`cognitive_ingest.py`** — extend `_apply_intent_certainty()`:

| Condition | `certainty` after ingest |
|-----------|--------------------------|
| Intent confidence &lt; `LOW_CONFIDENCE_THRESHOLD` | `tentative` (existing) |
| `store` intent, confidence ≥ threshold, extraction omitted certainty or left default | `confirmed` |
| Extraction explicitly sets `tentative` / `exploratory` / `confirmed` | Respect LLM value |

Rationale: default `tentative` blocks all auto-promotion even for high-confidence store intents. T1 already gates noise; confirmed is the promotion-ready tier.

## Wiring points

### 1. Cognitive ingest (post-extract)

After `_persist_sparks_from_extraction()` commits, call `promote_sparks_batch(..., manual=False, promotion_source="auto_ingest")` for returned `spark_ids`. Receipt metadata:

```python
"promotion": {"attempted": N, "promoted": M, "skipped": [...reasons...]}
```

### 2. Portable writeback acceptance

In `portable_context._impl_build_portable_writeback_acceptance_report()` when `apply=True` and spark accepted:

- Resolve linked `v4_spark_id` from memory_item metadata (already stored at ingest).
- Call `promote_spark_to_active(..., manual=True, promoted_by=reviewer, promotion_source="portable_acceptance")`.

Keeps V3 staged review gate; V4 `sparks` table finally aligns with memory_item promotion.

### 3. Manual seed

**`cognitive_maintenance.seed_manual_spark()`**:

- Option A (preferred): seed as `candidate`, then `promote_spark_to_active(..., manual=True, promotion_source="cognitive_seed")`.
- Return payload includes final `trust_state` (`active` on success).

### 4. Cognitive maintenance API

**`cognitive_maintenance.run_cognitive_maintenance()`** — surface `promotion_candidates` and `promotions_applied` from extended lifecycle result.

## Cold-start alignment (`context_resolution.py`)

### New counter

```python
def count_cold_start_sparks(conn, *, project_id: int | None = None) -> int:
    """
    Sparks that justify skipping memory_items fallback:
      trust_state IN ('active', 'pinned')
      OR (trust_state = 'candidate' AND certainty = 'confirmed')
    """
```

`count_active_sparks()` **unchanged** — strict active/pinned count for trace/debug.

### Threshold tune

```python
COLD_START_ACTIVE_SPARK_THRESHOLD = 8  # was 10
```

**`context_orchestration.py`**: use `count_cold_start_sparks()` for `fallback_used` decision; trace includes both counts:

```python
trace["active_spark_count"] = count_active_sparks(...)
trace["cold_start_spark_count"] = count_cold_start_sparks(...)
trace["fallback_used"] = cold_start_count < COLD_START_ACTIVE_SPARK_THRESHOLD
```

Effect: confirmed candidates count toward exiting cold start even before promotion runs; auto-promotion then moves them to `active` for clearer lifecycle.

## Retrieval certainty hook (`spark_retrieval.py`)

Read-time multiplier applied **after** canonical score computation (documented hook, not changing `W_*` weights):

```python
CERTAINTY_SCORE_MULTIPLIERS = {
    "confirmed": 1.00,
    "exploratory": 0.92,
    "tentative": 0.85,
}
```

```python
final_score = round(base_score * CERTAINTY_SCORE_MULTIPLIERS.get(certainty, 0.85), 4)
```

Expose in `score_breakdown["certainty_multiplier"]` when `debug=True`. Same inputs + same certainty → identical output (determinism preserved).
