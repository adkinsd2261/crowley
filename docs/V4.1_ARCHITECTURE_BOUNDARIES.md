# V4.1 Architecture Boundaries

**Status:** Shipped / locked
**Owner:** Codex  
**Applies to:** V4.1 tickets #317-#325  
**Baseline:** `crowley.py` at 10,218 lines / 336 top-level functions before
V4.1 extraction

V4.1 turns `crowley.py` into a compatibility facade over focused internal
domains. This document is the boundary contract for that work.

## Goals

- Make large subsystems discoverable by file and domain.
- Preserve all current imports, routes, CLI commands, sync payloads, Actions
  tools, and database behavior while code moves.
- Prepare a shared tool contract so future MCP can reuse the same tool
  definitions as ChatGPT Actions.
- Keep each extraction reversible and testable.

## Non-Goals

- No big-bang rewrite.
- No public API shape changes.
- No DB schema migrations.
- No MCP server in V4.1.
- No app router split in V4.1 unless required for a small compatibility adapter.
- No full Actions domain split in V4.1 beyond the shared tool-contract adapter.

## Dependency Direction

Allowed direction:

```text
app.py / chatgpt_actions.py / CLI
  -> crowley.py facade or focused domain modules
  -> domain modules
  -> crowley_core.py
```

Rules:

- Domain modules may import `crowley_core.py`.
- Domain modules should avoid importing `crowley.py`; if a circular dependency
  appears, introduce a small shared helper in `crowley_core.py` or a narrow
  interface function.
- `crowley.py` may import/re-export domain module functions for compatibility.
- `app.py` remains transport-only. New business logic must not be added there.
- `actions_tool_registry.py` remains an adapter over tool contracts and gates.
  New tool metadata should live in `crowley_tools.py` after #319/#320.

## Facade And Compatibility Rule

During V4.1, `import crowley` is a compatibility contract. Moving an
implementation must preserve the old symbol unless it was private and proven
unused.

Acceptable pattern:

```python
from memory_retrieval import retrieve_memories as retrieve_memories
```

or a thin wrapper when the old signature needs compatibility shims.

Not acceptable:

- Renaming public helpers used by `app.py`, scripts, tests, or V4 modules.
- Moving behavior and leaving callers to discover new imports in the same ticket.
- Changing response shapes while extracting.
- Adding new large features to `crowley.py`.

## `app.py` Boundary

`app.py` is prepare-only in V4.1. It currently owns FastAPI route declarations and
request/response translation. Future router split candidates:

- `routes_memory.py`
- `routes_cognitive.py`
- `routes_tickets.py`
- `routes_actions.py` stays in `chatgpt_actions.py`

V4.1 should not split those routers unless final QA proves a small adapter is
needed.

## Actions And MCP Boundary

ChatGPT Actions is the current external tool compatibility contract. V4.1 MCP
readiness must therefore flow through a shared tool contract rather than a
parallel registry.

Required shape after #319/#320:

```text
crowley_tools.py
  -> actions_tool_registry.py adapter
  -> /api/actions/catalog, /read, /write

future:
crowley_tools.py
  -> MCP transport adapter
```

MCP classification should be conservative:

- **MCP-safe read:** bounded read-only tools such as health/catalog/context,
  retrieval, memory/ticket get/list, cognitive context.
- **MCP-conditional write:** writeback parse/ingest, ticket create/update, handoff
  ingest only if the future MCP transport has equivalent auth, permissions,
  workflow gates, and audit.
- **Actions-only/local-only:** audit rollback, bridge operations, raw internal
  mutation paths, any future shell/deploy tools.
- **Blocked:** full internal `/api/*`, chat/session mutation without explicit
  authorization, local filesystem mutation, secret-bearing diagnostics.

## Extraction Stop Conditions

Stop the current ticket and reassess before continuing if:

- A domain move requires changing API response shapes.
- More than one unrelated subsystem must move to break an import cycle.
- A test failure points to behavior change rather than import location.
- A DB schema change appears necessary.
- Actions catalog identity or tool schemas drift unexpectedly.
