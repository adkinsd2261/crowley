## Manual workflow (packet-in / writeback-out)

```bash
# 1. Export a paste-ready Crowley packet (any surface label — model-agnostic)
./venv/bin/python3 scripts/export_portable_packet.py --surface chatgpt -o /tmp/crowley-packet.md

# 2. Paste the markdown into ChatGPT, Claude, or another reasoning surface.
#    End the external session with a fenced JSON writeback matching portable_writeback_contract().

# 3. Validate without saving (optional)
./venv/bin/python3 scripts/import_portable_writeback.py writeback.json --parse-only

# 4. Import into Crowley memory
./venv/bin/python3 scripts/import_portable_writeback.py writeback.json
```

HTTP equivalents:

- `GET /api/portable/packet?surface=chatgpt`
- `POST /api/portable/writeback/parse` — `{ "text": "..." }` or `{ "writeback": {...} }`
- `POST /api/portable/writeback/ingest` — same body shape as parse

Fixtures: `tests/fixtures/portable_writeback_valid.json`, `portable_writeback_invalid_spark.json`, `portable_packet_shape.json`.

## What gets saved

| Writeback field | Persisted? | Storage |
|-----------------|------------|---------|
| `session.summary` | Yes | Episodic receipt — `memory_type=summary`, `source=portable_terminal` |
| `sparks[]` | Yes (candidates) | `memory_type=event`, `status=staged`, `pinned=0` |
| `decisions`, `lessons`, … | Metadata on session receipt only | `metadata_json` on session row |
| `do_not_save` | **No** | Parsed and reported; never written to memory |
| Raw chat transcript | **No** | Not saved by default |

Spark candidates carry `lane`, `why_keep`, `worth_reason`, `confidence`, `sensitivity`, `surface`, `model`, `provider` in `metadata_json`.

---

## Trust rules and sensitive lanes

- **Staged, not canon** — imported sparks use `status=staged`; they do not enter hybrid retrieval until promoted to `active`.
- **Never auto-pinned** — portable terminal ingest never sets `pinned=1` on sparks.
- **Sensitive handling** — `sensitivity: sensitive` or `high` lowers importance and keeps staged/candidate handling; no auto-promotion to canon.
- **Review boundary** — operator promotes staged sparks manually (future V4 trust states will formalize this).
- **`do_not_save` is discard-only** — parser accepts it; ingest skips persistence entirely.

---

## V4 boundary

**V3.9.12 proves the manual terminal loop.** It does not ship:

- OAuth, browser extension, or live terminal automation  
- Cloud sync  
- Durable Spark Lanes schema migration  

**V4.0 owns Spark Lanes architecture** — sparks as the memory unit, lane-aware retrieval, trust states (candidate → active → canon), and pattern synthesis. Lanes introduced in writeback (`learning`, `work`, `relationships`, `money`, `health`, `operating_style`) foreshadow V4 but remain staged metadata in V3.9.12.
