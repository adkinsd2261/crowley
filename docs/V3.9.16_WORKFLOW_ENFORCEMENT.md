# Crowley V3.9.16 — Workflow Enforcement

**Status:** Shipped (2026-07-06)  
**Release:** `CROWLEY_VERSION = "3.9.16"`, `Crowley V3.9.16 Workflow Enforcement`  
**Tickets:** #101–#111

---

## 1. Purpose

V3.9.15 proved the GPT Toolbelt. V3.9.16 **enforces** the workflow loop so fresh chats, builder handoffs, and ChatGPT Actions sessions stay grounded in latest Crowley state.

---

## 2. Boot sequence (#101)

Every fresh ChatGPT Actions session must call **`agent.sync`** before other tools.

| Surface | Enforcement |
|---------|-------------|
| ChatGPT Actions | Runtime gate — `428 boot_required` until `agent.sync` |
| Cursor | Hooks + `cursor_sync.py --before` (unchanged) |
| Codex | `codex_sync.py --before` (unchanged) |

Exempt tools (no prior sync): `agent.sync`, `context.get`, `portable.packet`.

Session tracking: optional `X-Crowley-Session` header; falls back to bearer hash.

---

## 3. Truth hierarchy (#102)

For **what changed** and **what now**, agent activity timestamps beat `project_state` and beat supporting memory.

Prompt injection order updated: filesystem → **tickets** → **agent activity** → project state → task frame → canon → retrieval.

See [MEMORY_HIERARCHY.md](./MEMORY_HIERARCHY.md) — V3.9.16 adds explicit activity-over-state rule in `_ground_truth_prompt()`.
