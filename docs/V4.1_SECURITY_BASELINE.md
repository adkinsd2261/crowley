# V4.1 Security Baseline

**Status:** Shipped / locked
**Owner:** Codex  
**Scope:** Local-first hardening for V4.1 architecture work

Crowley is a local personal system with a narrow external Actions bridge. V4.1
does not turn Crowley into a public multi-user service; it makes the existing
trust model explicit, tested, and harder to accidentally weaken during the
architecture refactor.

## Trust Boundaries

| Surface | Exposure | Security expectation |
|---------|----------|----------------------|
| Browser UI and internal `/api/*` | `127.0.0.1:8765` only | Trusted local operator; no auth required in V4.1 |
| `/api/actions/*` | Local and optional public tunnel | Requires `CROWLEY_ACTION_KEY` bearer or `X-API-Key` |
| Cloudflare named tunnel | Optional public hostname | Must forward only `^/api/actions/.*`; all other paths 404 |
| SQLite database | Local filesystem | Not encrypted in V4.1; do not expose directly |
| Memory/sparks returned to model surfaces | API and Actions context | Bounded, sensitivity-gated, and output-sanitized |

## In Scope

- Keep Crowley bound to localhost by default.
- Keep `/api/actions/*` disabled when `CROWLEY_ACTION_KEY` is unset.
- Keep missing/wrong Actions credentials at `401`.
- Keep public tunnel ingress limited to `/api/actions/*`.
- Keep direct mutation entrypoints behind dispatch invariant checks.
- Keep Actions write tools behind agent permissions and automation guardrails.
- Keep cognitive context output redacted and wrapped in `MEMORY_DATA`.
- Reject secret-like spark content at validation time.
- Add a read-only secret hygiene report for raw memory and log-adjacent text.

## Out Of Scope

- OAuth, user accounts, browser sessions, or multi-user isolation.
- Requiring auth for localhost UI/internal routes.
- Public hosting of the full `/api/*` tree.
- Field-level encryption.
- Automatic deletion, rewriting, or quarantine of detected secret-like text.
- Shell, deploy, or filesystem mutation tools.

## Regression Gates

Existing tests already cover most of the boundary:

- `tests/test_chatgpt_actions_api.py`: Actions bearer behavior and legacy aliases.
- `tests/test_security_hardening.py`: observability integrity, tunnel boundary,
  dispatch gates, and invariant coverage.
- `tests/test_actions_write_tools.py`: write-tool permission and writeback paths.
- `tests/test_agent_identity.py`: write/domain permission denial.
- `tests/test_cognitive_api_limits.py`: cognitive ingest caps and rate limits.
- `tests/test_spark_sanitize.py`: output redaction and `MEMORY_DATA` wrapping.
- `tests/test_spark_security_validation.py`: spark write-time secret and prompt
  injection rejection.

V4.1 adds:

- `security_hygiene.py`: read-only likely-secret scanning.
- `tests/test_secret_hygiene.py`: audit redaction, read-only behavior, and log
  scanning fixtures.

## Secret Hygiene Report

The secret hygiene report is an audit, not a cleanup job.

It scans:

- `memory_items.summary`
- `memory_items.content`
- `memory_items.metadata_json`
- optional log files passed to the report helper
- default local Crowley log paths when enabled

It reports:

- finding kind
- source and field
- record id or log filename
- offset
- redacted excerpt

It never reports the raw matched secret, and it never mutates the database or
log files.

## Operator Checklist

Before exposing ChatGPT Actions publicly:

1. Confirm Crowley listens on `127.0.0.1`, not `0.0.0.0`.
2. Set a long random `CROWLEY_ACTION_KEY`.
3. Verify `/api/actions/health` returns `503` when the key is missing.
4. Verify `/api/actions/health` returns `401` for a wrong bearer.
5. Verify `/api/actions/health` returns `200` for the correct bearer.
6. Verify the public hostname returns `404` for `/`, `/api/health`, and any
   non-Actions path.
7. Rotate `CROWLEY_ACTION_KEY` if it appears in chat, logs, handoffs, or memory.

## V4.1 Rule

Any architecture extraction that changes this boundary must stop and become a
separate security design decision. Refactor tickets are not allowed to silently
broaden public exposure.
