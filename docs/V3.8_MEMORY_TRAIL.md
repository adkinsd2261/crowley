# Crowley V3.8 — Memory Trail

**Status:** Shipped (2026-07-01)  
**Release:** `CROWLEY_VERSION = "3.8"`, `CROWLEY_RELEASE_LABEL = "Crowley V3.8 Memory Trail"`  
**Baseline:** V3.7.3 memory consolidation + V3.7 context bridge

---

## 1. Purpose

V3.8 makes Crowley's memory **inspectable and trustworthy** for humans and external agents:

1. **Phase A — UI/API truth** — real memory counts and filterable memory list (not "10 = total").
2. **Phase B — Canon read path** — pinned summary memories as a separate "canonical trail" in prompts and agent sync.
3. **Phase C — Canon synthesis** — manual writer that archives old canon and inserts six validated layers.
4. **Multi-agent sync** — Codex and Cursor post handoffs to Crowley; agents read each other only via `/api/agent/sync`.

---

## 2. Shipped surface

### HTTP API (`127.0.0.1:8765`)

| Method | Path | Engine | Role |
|--------|------|--------|------|
| GET | `/api/memory-items` | `list_memory_items()` | Filtered/paginated memory for UI |
| GET | `/api/agent/sync` | `build_agent_sync_bundle()` | Per-agent context + `canon` + cross-agent events |
| GET | `/api/world` | `build_world_dashboard()` | Now includes truthful `memory_*` counts (V3.8) |
| GET | `/api/context` | `build_context_bundle()` | Now includes top-level `canon` (V3.8) |

### Memory tab UI

- Tab badge: `Memory (N)` from `memory_active`
- Count line: `N active / M total · showing K`
- Filters: search, source, memory type, status

### Canon model

Canon rows are existing `memory_items`:

- `status = 'active'`
- `pinned = 1`
- `source = 'crowley'`
- `memory_type = 'summary'`
- `content` starts with `Canon:`

Canon is **excluded** from `events_from_other_agents` and exposed as top-level `canon` in `/api/context` and `/api/agent/sync`.

### Prompt precedence

```
project_state + knowledge files  >  canon  >  hybrid retrieval  >  recent chat
```

`build_prompt()` injects canon after knowledge files and before hybrid retrieval.

### Scripts

```bash
# Canon synthesis (dry-run by default)
./venv/bin/python3 scripts/synthesize_canon.py --show-packet
./venv/bin/python3 scripts/synthesize_canon.py --write   # after valid model output

# Multi-agent sync
./venv/bin/python3 scripts/codex_sync.py --before
./venv/bin/python3 scripts/cursor_sync.py --before
./venv/bin/python3 scripts/ensure_crowley_bus.sh
```

Six canon layers on `--write`: Project, Agents, Decisions, Work, Mr. Go, Recent.

## 3. API reference (abbreviated)

### GET /api/memory-items

Query: `q`, `source`, `memory_type`, `status` (default `active`), `limit` (default 10), `offset`.

Returns: `{ items, total, limit, offset, filters }`.

### GET /api/agent/sync

Query: `agent` (`cursor` | `codex`, required), `limit` (default 8).

Returns: `bus_health`, `project`, `state`, `canon`, `agent_activity`, `events_from_other_agents`, `events_from_this_agent`, `open_tasks`, `open_loops`, `recent_decisions`, `relevant_memories`, `recommended_next_action`.

### GET /api/world (counts)

`counts` now includes:

- `memory_active`, `memory_total`, `memory_displayed`
- `memory_by_status` — e.g. `{ active, merged, stale, archived }`

## 4. Multi-agent hub

Crowley is the **only** hub. Codex and Cursor do not message each other directly.

| Agent | Script | Handoff types |
|-------|--------|---------------|
| Codex | `scripts/codex_sync.py` | `architect_handoff`, `builder_handoff`, `note` |
| Cursor | `scripts/cursor_sync.py` | `builder_handoff`, `note` |

Both scripts refuse placeholder/empty scaffolds at ingest time.

Cursor hooks (`.cursor/hooks.json`): `sessionStart` + `beforeSubmitPrompt` → `cursor_sync.py --before`; `stop` → `--session-end` (V3.8.1).

**Follow-on:** [V3.8.1_AGENT_PARITY.md](./V3.8.1_AGENT_PARITY.md) — `agent_activity` in API bundles, shared verify, session-end enforcement.

## 5. Explicitly out of scope

- Auto canon synthesis on every ingest (manual-first)
- Mixing canon into agent event feeds
- Canon overriding project_state or knowledge files
- Direct Codex ↔ Cursor communication
