# Crowley V3.9.2 — Canon Synthesis Workflow

**Status:** Shipped (first run complete)  
**Baseline:** V3.9.1 Repository & CI  
**Script:** `scripts/synthesize_canon.py`

---

## 1. Purpose

Canon is Crowley's **always-on continuity layer** — six pinned `Canon:` rows in `memory_items` that summarize project, agents, decisions, work, Mr. Go preferences, and recent context.

Synthesis is **manual-first**: inspect the source packet, dry-run, review validation, then write only when validation passes. Failed validation is **non-destructive** — no archive, no insert.

---

## 2. Memory hierarchy (where canon sits)

**Authority order for facts** (highest → lowest):

1. Filesystem docs (`VERSIONS.md`, `docs/WHERE_WE_ARE.md`, phase docs)
2. Tickets (`/api/tickets`)
3. Agent activity (`last_by_source` on sync bundles)
4. `project_state` (SQLite — may lag docs slightly)
5. **Canon** (pinned `Canon:` rows — continuity, not override)
6. Hybrid retrieval (`/api/retrieve` — supporting context only)
7. Recent chat window

**Prompt injection order** (what Crowley sees in chat):

```
Filesystem truth (knowledge files)  →  Canon  →  Hybrid retrieval  →  chat history
```

Canon sits **below filesystem truth and project_state for factual authority**, but **above hybrid retrieval** in both authority and prompt placement. See `build_prompt()` in `crowley.py` and ADR in `docs/V3.8_MEMORY_TRAIL.md`.

## 3. Operator workflow (required sequence)

Run from repo root with the venv Python and Crowley bus healthy (`./scripts/ensure_crowley_bus.sh`).

### Step 1 — Inspect source packet

```bash
./venv/bin/python3 scripts/synthesize_canon.py --show-packet | less
```

Review what the model will see: `project_state`, decisions, open loops, tasks, memory items (excluding existing canon), knowledge doc excerpts, recent unsummarized messages.

**Do not skip this** before the first `--write` on a machine or after major project changes.

### Step 2 — Dry-run synthesis (default)

```bash
./venv/bin/python3 scripts/synthesize_canon.py
```

Expected success output:

```json
{
  "status": "ok",
  "dry_run": true,
  "layers": ["Canon: Project", "Canon: Agents", ...],
  "would_write": 6
}
```

This calls the model but **writes nothing**. Row counts in `crowley.db` must be unchanged.

### Step 3 — Review validation

Validation runs automatically on model output. Each of six layers must:

- Be non-empty
- Include at least one evidence marker (`memory_items:N`, `decision:N`, `docs/….md`, `VERSIONS.md`, etc.)
- Contain no secret-like patterns (API keys, tokens, passwords)

On failure:

```json
{
  "status": "error",
  "dry_run": false,
  "errors": ["missing evidence marker: Canon: Decisions", ...]
}
```

**No database changes occur on validation failure.**

To test failure handling without the model:

```bash
./venv/bin/python3 -m unittest tests.test_memory_trail.SynthesizeCanonTests.test_invalid_output_fails_closed -q
```

### Step 4 — Write (only after Steps 1–3 pass)

```bash
./venv/bin/python3 scripts/synthesize_canon.py --write
```

Expected success output:

```json
{
  "status": "ok",
  "dry_run": false,
  "archived": <N>,
  "inserted": 6,
  "inserted_ids": [...]
}
```

**Write behavior:**

1. Archive all active pinned `Canon:` rows for the project (`status = archived`)
2. Insert six new pinned canon rows (`Canon: Project`, `Agents`, `Decisions`, `Work`, `Mr. Go`, `Recent`)
3. Commit in a single transaction (rollback on error)

### Step 5 — Verify

```bash
./venv/bin/python3 -c "
import crowley
crowley.setup_db()
p = crowley.get_active_project()
rows = crowley.list_canon_memory_items(int(p['id']))
print(f'active canon layers: {len(rows)}')
for r in rows:
    print(f\"  #{r['id']} {r['summary']}\")
"
```

Expect **6 active** canon layers. Prior canon rows should show `status = archived`.

## 5. When to re-run

- After a major release ships (version bump + doc sweep)
- After Codex posts a large architect handoff that changes direction
- When canon content is stale vs `docs/WHERE_WE_ARE.md` or ticket board
- **Not** on every ingest — auto/debounced synthesis remains out of scope (see open loop)

Always repeat Steps 1–3 before `--write`.
