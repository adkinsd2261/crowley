# Crowley V3.7 — Context Bridge

**Status:** Shipped (2026-06-30), updated through V3.8.1 (2026-07-01)  
**Release:** `CROWLEY_VERSION = "3.8.1"`, `CROWLEY_RELEASE_LABEL = "Crowley V3.8.1 Agent Parity"`  
**Baseline:** V3.6 memory backend (hybrid retrieval, dual-write, chat context)

---

## 1. Purpose

Crowley V3.7 is the **context bridge** between Crowley's local brain and external tools (Cursor, ChatGPT, Codex). External agents can read project truth, search memory, and submit handoffs without MCP, auth, or cloud sync.

Crowley owns memory and world model. External tools submit observations; Crowley decides what becomes `memory_item`, decision, or state update.

V3.7.1 added truth guards and greeting fixes. V3.7.2 added knowledge files context, live UI dashboard, and Cursor memory sync. V3.7.3 added memory consolidation (`POST /api/consolidate`). V3.8 added Memory Trail (truthful memory API/UI, canon path) and multi-agent sync (`GET /api/agent/sync`, `codex_sync.py`, `cursor_sync.py`). See [V3.8_MEMORY_TRAIL.md](./V3.8_MEMORY_TRAIL.md).

### File workflow

```
.crowley/inbox/          ← drop .md / .txt handoffs
.crowley/processed/      ← moved after successful ingest

scripts/crowley_handoff.py   → write template to inbox
scripts/ingest_inbox.py      → ingest inbox files (engine or --via-http)
scripts/sync_backlog.py      → dedupe tasks, seed loops
scripts/finalize_live_ui_backlog.py → close completed initiative loops
```

## 3. API reference (abbreviated)

### GET /api/context

Query: `q` (default `current project state`), `limit` (default 8), `project` (optional slug).

Returns: `project`, `state`, `recent_decisions`, `open_loops`, `open_tasks`, `relevant_memories`, `knowledge_files`, `project_files`, `system_health`, `recommended_next_action`.

### GET /api/world (V3.7.2)

Returns: `project`, `state`, `phase_progress`, `version`, `release_label`, `counts`, `tasks`, `loops`, `decisions`, `memory_items`, `synced_at`.

### GET /api/retrieve

Query: `q` (required), `limit` (default 8).

Returns: `query`, `limit`, `retrieval_mode`, `results`.

### POST /api/ingest

```json
{
  "source": "cursor",
  "type": "builder_handoff",
  "project": "crowley",
  "content": "...",
  "metadata": {}
}
```

Writes `memory_items` only (no legacy `memories`, no `messages`). Optional conservative world-model extraction at confidence ≥ 0.85. Version claims validated against knowledge files.

### GET /api/bus/health

Returns: `status`, `version`, `release_label`, `active_project`, `routes`, `db`, `retrieval_mode`, `provider`, `brain`.

## 4. Scripts

### crowley_handoff.py

```bash
./venv/bin/python3 scripts/crowley_handoff.py --source cursor --type builder_handoff --from-git
./venv/bin/python3 scripts/crowley_handoff.py --include-diff --from-git  # optional diff
```

Flags: `--source`, `--type`, `--project`, `--from-git`, `--include-diff`.

### ingest_inbox.py

```bash
./venv/bin/python3 scripts/ingest_inbox.py
./venv/bin/python3 scripts/ingest_inbox.py --via-http
```

Filename inference: `cursor_*` → source cursor; `*builder*` → builder_handoff; etc.

## 6. Known limitations

| Limitation | Notes |
|------------|-------|
| Legacy sparks API | `/api/sparks` reads legacy `memories`; UI uses `/api/memory-items` |
| `metadata` on ingest | Accepted, not persisted |
| Localhost only | `127.0.0.1:8765`, no auth |
| Ingest filename inference | Scripts infer source/type from filename, not markdown header |
| sqlite-vec | Optional; blob cosine fallback on some platforms |
| Memory consolidation | ✅ V3.7.3 — `POST /api/consolidate`, `--consolidate` CLI |
| Memory Trail / canon | ✅ V3.8 — see [V3.8_MEMORY_TRAIL.md](./V3.8_MEMORY_TRAIL.md) |
