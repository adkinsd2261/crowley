## 1. Purpose

V3.9.18 enforced retrieval at the Actions gateway. V3.9.19 improves **memory quality** (ingest dedup, retrieval strength, lifecycle cleanup) and makes **pre-response validation** reflect live observability on every sync path — including `GET /api/agent/sync` used by Cursor/Codex hooks.

---

## 2. Ingest dedup (#153–#155)

- `memory_quality.py` — constraint semantic dedup (0.65 similarity, 90-day lookback); semantic dedup for `summary`, `project_update`, `lesson`, `event` (0.85, 72h)
- Opposing constraints preserved for conflict detection (`_constraints_are_conflicting`)
- Wired into `save_memory_item` ingest path via `find_ingest_duplicate()`

## 3. Retrieval strength (#154, #156)

- `assess_retrieval_strength()` — `strong|moderate|weak` on `/api/retrieve` (non-blocking)
- Rebalanced hybrid weights: semantic **0.50**, importance **0.12**, recency **0.08** (was 0.45/0.10/0.15)

## 6. Runtime wiring (#166)

**Problem:** Live sync showed `pre_response_validation.ready=false` — tests passed but runtime order was wrong.

**Fix:**

| Path | Behavior |
|------|----------|
| `actions_tool_registry.dispatch()` | `dispatch_id` allocated **before** handler; `record_dispatch_observability` **after** handler; `attach_agent_sync_runtime()` for `agent.sync` |
| `GET /api/agent/sync` | Same wiring with session key `agent:{agent}` (e.g. `agent:cursor`) |
| `_handle_agent_sync` | Builds bundle only — no premature validation |

**New helpers in `agent_behavior.py`:**

- `begin_dispatch(session_key, dispatch_id)` — request-scoped observability binding
- `attach_agent_sync_runtime()` — shared post-record validation attachment
- `record_agent_sync_dispatch()` — registers `agent.sync` with dispatch_id
- `validate_retrieval_state(..., dispatch_id=...)` — dispatch-scoped `tools_called` + observability metadata
