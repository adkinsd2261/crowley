# Crowley V3.9.5 -- Conversation + Model Behavior

**Status:** Planned
**Baseline:** V3.9.4 (`Crowley V3.9.4 Agent Visibility`)
**Plan:** [PRE_V4_QUALITY_PLAN.md](./PRE_V4_QUALITY_PLAN.md)

---

## 1. Goal

Make Crowley pleasant to talk to daily: warm, useful, mode-aware, and able to move between quick status answers and deeper planning without a visible UI toggle.

Done when Mr. Go prefers Crowley over a raw model chat for project work.

---

## 2. Scope

| Ticket | Slice | Outcome |
|--------|-------|---------|
| #25 | Conversation mode classifier | Deterministic inferred mode appears in prompt with answer shape |
| #26 | Response depth controller | `brief`, `standard`, and `deep` are selected predictably |
| #27 | Personality trim | `_personality_prompt()` is co-founder shaped, less theatrical |
| #28 | Diagnostics tone separation | Diagnostics stays factual and does not inherit chat persona |
| #29 | Regression fixtures | Prompt/controller behavior covered without live model calls |
| #30 | Chat bug sweep | Confirmed chat UX bugs fixed without feature creep |

---

## 3. Non-goals

- No manual conversation-mode toggle.
- No live model-quality assertions.
- No provider routing changes.
- No new agent channels or direct Codex-to-Cursor messaging.
- No broad chat redesign in this release.

---

## 4. Acceptance gate

- Common phrasings classify into `status`, `planning`, `exploration`, `debug`, `diagnostics`, `bug`, or `casual`.
- Depth defaults to `standard`, becomes `brief` for status/check/update asks, and `deep` for planning/exploration.
- Prompt assembly includes mode, depth, and expected answer shape.
- Diagnostics prompt remains SQL/fact-first.
- Quick updates stay short; V4/planning thoughts can expand.
- Tests cover deterministic controller behavior.

---

## 5. QA

- Focused unit tests for classifier, depth controller, prompt assembly, and diagnostics separation.
- Chat UX tests for any fixed empty/error/streaming bug.
- Full regression: `python -m unittest discover -s tests -q`.
- Manual QA with:
  - "what changed?"
  - "any update from Cursor?"
  - "thoughts on V4?"
  - diagnostics trigger
  - a feasible model-error or empty-state path
