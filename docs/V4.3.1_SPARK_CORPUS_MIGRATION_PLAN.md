# V4.3.1 Spark Corpus Migration — Plan

**Status:** Implementing · packet `tickets/v4.3.1_spark_corpus_migration.json`  
**Version:** `CROWLEY_VERSION` stays `4.1.0` (no bump)  
**Depends on:** V4.3 Retrieval + Query lock

## Goal

Seed a real living spark corpus from valuable `memory_items` before V4.4 chat wire, without bulk-dumping ~2500 rows and without deleting receipts.

## Roles

| Store | Role after migration |
|-------|----------------------|
| `sparks` | Living cognitive store (retrieval + map + future chat) |
| `memory_items` | Receipts, canon audit, ticket memory, cold-start fallback |
| `memories` (legacy V2) | Untouched by this packet |

**Hard rule:** `memory_items` remain intact. No deletion, no table removal, no bulk archive in V4.3.1.

## Migrate / include rules

Include **active** rows that are high-signal:

- Pinned canon summaries
- Decisions, constraints, lessons, preferences
- High-importance (`>= 4`) project updates
- Canon / manual / portable_terminal / consolidation sources when type is durable

## Exclude rules

- Status `merged`, `rejected`, `staged` (and any non-`active`)
- Rows already represented by `sparks.source_memory_item_id`
- Obvious handoff receipts / agent sync chatter (unless durable decision/constraint/lesson/preference)
- QA-only noise and side-quest / quarantine recovery notes (unless pinned or importance ≥ 4)
- Low-signal `event` / unpinned low-importance `project_update`
- Duplicate summary fingerprints (keep first by rank)

## Trust policy

| Case | Default `trust_state` |
|------|------------------------|
| Normal migrate | `candidate` |
| Pinned + canon | may set `pinned` on apply |
| Canon/pinned confirmed decision (or canon confirmed constraint) | may promote `active` via documented policy |
| Ambiguous / long / clipped | stay `candidate` with lower confidence |

LLM never sets trust. Apply path defaults to `candidate`; promotion is deterministic policy only.

## Extraction paths

1. **Deterministic short** (≤ 280 chars): map type → `spark_type` / lane / certainty; `validate_spark`
2. **Short clip** for long rows without `--with-llm`: clip + tentative certainty
3. **LLM** (`spark_extraction.extract_sparks_from_text`) only when `--with-llm` and content is long

Every proposed spark must:

- Pass `sparks.validate_spark`
- Be atomic and ≤ 300 chars
- Include `source_memory_item_id` and `lineage_json.migration_batch_id`

## Apply gates

- Dry-run report required before any apply
- `--apply` **and** explicit bounded `--limit` required
- Soft cap: `--limit` ≤ 50 per run (small auditable batches)
- Use `sparks.upsert_spark_with_dedup` (insert / link / merge)
- Idempotent: already-linked `source_memory_item_id` skipped
- Never mutate `memory_items` status/content in apply

## Anti-patterns

- Bulk `INSERT SELECT` from `memory_items` → `sparks`
- Deleting or bulk-archiving `memory_items` to “clean”
- Changing V4.3 query/scoring/lane/cap contracts
- Rewriting `crowley.py` facade or bumping `CROWLEY_VERSION`
- Claiming V4.4 `#363` before T5 lock approval
