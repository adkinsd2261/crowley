# V4.1 Architecture, Security, and MCP Readiness Ledger

**Status:** Planned / in progress  
**Owner:** Codex  
**Baseline:** V4.0.0 Cognitive Memory shipped  
**Ticket packet:** `tickets/v4.1_architecture_security_mcp.json` (#316-#325)

V4.1 is a foundation release. It should make Crowley easier to reason about,
safer to operate locally, and ready for a future MCP transport without changing
the user-facing API, CLI, sync, Actions, or database contracts that already work.

## Included Now

- Lock the V4 post-ship audit fix before architecture work begins.
- Document the current `crowley.py` domains and target module boundaries.
- Add a local-first security baseline with regression tests.
- Create a transport-neutral Crowley tool contract that existing ChatGPT Actions
  can consume.
- Keep ChatGPT Actions as the compatibility contract while preparing future MCP.
- Extract `crowley.py` in staged slices with compatibility re-exports.
- Preserve existing HTTP routes, CLI commands, sync payloads, Actions tools, and
  DB schema.
- Finish with a V4.1 architecture audit, QA lock, and remaining-debt register.

## Prepared Only

- **MCP transport:** V4.1 defines tool contracts and exposure classification, but
  it does not ship or run an MCP server.
- **`app.py` router split:** V4.1 documents route boundaries, but keeps FastAPI
  routes in place unless a tiny adapter is required for tests.
- **Actions registry domain split:** V4.1 introduces shared contracts, but does
  not fully split Actions registration into separate domain files.
- **Migration framework:** V4.1 records the migration debt, but does not add a
  full schema versioning system.

## Explicitly Deferred

- Field-level encryption for stored memory or sparks.
- Cognitive review UX for approving, pinning, rejecting, or tuning sparks and
  patterns.
- Truth arbitration for large-scale spark sets and conflicting/time-sensitive
  memories.
- Workflow determinism beyond preserving existing Actions gates and sync
  behavior.
- Voice, TTS, speaker, glasses, or device work.
- Event-driven automation.
- OAuth, accounts, multi-user isolation, or public full-API hosting.
- Auth requirements for localhost UI/internal routes.

## Security Posture

- Crowley remains local-first and bound to `127.0.0.1` by default.
- Full internal `/api/*` remains trusted-local only.
- Public exposure remains limited to `/api/actions/*` through the API-only tunnel
  configuration.
- `/api/actions/*` remains bearer-gated by `CROWLEY_ACTION_KEY`.
- V4.1 adds tests and read-only audits for the expected boundary; it does not
  turn Crowley into a public SaaS service.

## Non-Regression Bar

Every V4.1 ticket must preserve:

- `/api/health`, `/api/world`, `/api/context`, `/api/retrieve`, and
  `/api/cognitive/context` response behavior.
- `/api/agent/sync` and `agent.deep_sync` payload compatibility.
- `/api/portable/*` and terminal writeback behavior.
- ChatGPT Actions catalog, read/write gateway, legacy aliases, boot gate,
  permissions, timeouts, and observability.
- `python crowley.py` CLI behavior.
- Existing `import crowley` call sites via facade re-exports.
- V4 cognitive ingest, spark validation, retrieval, sanitization, lifecycle,
  observability, and lineage behavior.

## Baseline Closure

The V4 post-ship audit found a cold-start cognitive context fallback SQLite lock.
The fix makes `crowley.retrieve_memories()` accept an optional active connection
and makes `context_orchestration._memory_fallback_items()` reuse that connection.
That fix is part of the V4.1 starting baseline and must remain covered by
cognitive context tests.
