# Crowley V3.9.17 — Trust, Control, and Clarity

**Status:** Shipped (2026-07-06)  
**Release:** `CROWLEY_VERSION = "3.9.17"`, `Crowley V3.9.17 Trust Control and Clarity`  
**Tickets:** #112–#130

---

## 1. Purpose

V3.9.16 enforced the workflow loop. V3.9.17 adds **trust and control** over writes and memory, plus an **agent behavior layer** so ChatGPT/Codex sessions retrieve before answering instead of guessing.

Two arcs shipped together:

| Arc | Tickets | Focus |
|-----|---------|-------|
| Trust / Control / Clarity | #112–#122 | Attribution, permissions, audit, memory tiers, conflicts |
| Agent behavior | #123–#130 | Sync policy, retrieval policy, chaining, validation, observability |

---

## 2. Write attribution and permissions (#112–#113)

- `agent_identity.py` — `agent_id`, source, timestamp, signature on writes
- Scoped roles: `read_only`, `writer`, `architect`
- `X-Crowley-Agent` header on Actions API
- Permission gate on ticket create/cancel and write tools

---

## 3. Write audit and rollback (#114)

- `write_audit.py` — append-only `write_audit_log` table
- `inspect.audit_list` and `audit.rollback` Actions tools
- Rollback paths for memory, tickets, handoffs

---

## 4. Memory tiers (#115–#116)

- `memory_tiers.py` — ephemeral / working / canonical tiers in metadata
- Promotion via `POST /api/memory/{id}/promote` (architect gate)
- Decay/GC via `POST /api/memory/gc`
- Tier boost in hybrid retrieval scoring

---

## 5. Conflict detection and resolution (#117–#118)

- `conflict_engine.py` — detect contradictory same-topic pairs
- `memory_conflicts` table; `GET/POST /api/memory/conflicts/*`
- Deterministic resolution with `resolution_trace`

---

## 6. Retrieval explainability (#119–#122)

- `GET /api/retrieve/explain` — why a memory was retrieved
- `GET /api/session/changes` — session-scoped change summary
- `GET /api/mode/simple` — simplified mode hint for agents
- Permissions schema in workflow/catalog payload

---

## 7. Agent behavior layer (#123–#130)

`agent_behavior.py` — instruction and state layer (not a backend router):

| Ticket | Feature |
|--------|---------|
| #123 | Mandatory `agent.sync` for system-level queries; sync dedup per request cycle |
| #124 | `recent_handoffs` auto-loaded in sync bundle after `agent.sync` |
| #125 | `RETRIEVAL_POLICY` — intent → tool mapping (tickets, recent work, code, memory, system) |
| #126 | `CHAINING_POLICY` — max 3 chained reads; `chain_depth` tracked |
| #127 | `MANDATORY_RETRIEVAL_RULES` — domain tools required before answering |
| #128 | `PRE_RESPONSE_CHECKLIST` — sync, handoffs, domain data validation |
| #129 | `QA_PIPELINE_SCHEMA.crowley_context_validation` for Codex QA stage |
| #130 | `inspect.retrieval_observability` — per-session tool log and validation |

Wired into `actions_tool_registry.dispatch()` (sync gate + `record_tool_call`) and `agent.sync` response (`agent_behavior`, `pre_response_validation`).
