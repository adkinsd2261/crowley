# V4.3.2 Spark Corpus Expansion + Legacy Demotion — Plan

**Status:** Implementing · packet `tickets/v4.3.2_spark_corpus_expansion_legacy_demotion.json`  
**Version:** `CROWLEY_VERSION` stays `4.1.0` (no bump)  
**Depends on:** V4.3.1 Spark Corpus Migration lock

## Goal

Aggressively grow the V4 spark corpus so sparks become the single living cognitive log before V4.4 chat wire. Preserve `memory_items` as receipts/audit; demote/archive only after lineage or deterministic noise classification (T4). No DELETE.

## Coverage targets (T1)

| Target | Minimum |
|--------|--------:|
| Active or pinned sparks | 50 |
| Sparks with `source_memory_item_id` lineage | 200 |
| Active memory_items without spark lineage | ≤ 400 |
| Tier A migrated (progress toward) | 20 |
| Tier B migrated (progress toward) | 80 |

Report via:

```bash
./venv/bin/python3 scripts/select_memory_spark_candidates.py --coverage --write
```

## Candidate tiers

| Tier | Meaning | Migrate? |
|------|---------|----------|
| **A** | Canon / pinned / current-state durable rows | Yes (first) |
| **B** | Durable decisions, constraints, preferences, lessons | Yes |
| **C** | High-signal project updates (pinned or importance ≥ 4) | Yes |
| **D** | Receipts, QA noise, side-quest recovery, ticket approval/denial chatter | **No** (unless manually whitelisted later) |

Tier A/B always rank before ticket approval chatter (Tier D excluded).

## Expansion rules (T2+)

- Dry-run artifact required before apply (or explicit `--reviewed`)
- Batches capped (default ≤ 50); unique `migration_batch_id` per batch
- Idempotent: already-linked `source_memory_item_id` skipped
- Default trust remains `candidate`; promotion is a separate reviewed step (T3)

## Demotion rules (T4)

- No DELETE of `memory_items`
- Archive/stale only with spark lineage or deterministic low-value classification
- Protect pinned/canon/ticket-linked receipts unless represented by active/pinned sparks

## Anti-patterns

- Bulk dump all memory_items as active sparks
- Broad auto-promotion of ticket chatter
- Archiving before spark coverage exists
- Changing V4.3 query/scoring/lane/cap contracts
- Bumping `CROWLEY_VERSION` or rewriting `crowley.py`

## Scripts

| Script | Role |
|--------|------|
| `scripts/select_memory_spark_candidates.py` | Tiers + coverage |
| `scripts/extract_memory_items_to_sparks.py` | Multi-batch expansion (T2) |
| `scripts/review_migrated_sparks.py` | Promotion review (T3) |
| `scripts/archive_migrated_memory_items.py` | Legacy demotion (T4) |
