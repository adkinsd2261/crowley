## Scope

V3.9.12 proved manual packet-in/writeback-out. V3.9.13 adds a **narrow authenticated HTTP surface** so a ChatGPT Custom GPT can call Crowley over HTTPS (via operator tunnel) without exposing tickets, chat, brain switching, or the full internal API.

| In scope | Out of scope |
|----------|--------------|
| Bearer-auth `/api/actions/*` | OAuth, browser extension |
| `CROWLEY_ACTION_KEY` env gate | Binding to `0.0.0.0` |
| Context, retrieve, portable packet, writeback parse/ingest | Ticket/task mutation, `/api/chat`, diagnostics |
| `openapi-chatgpt.json` for Custom GPT import | Auto-configured Cloudflare tunnel or GPT |
| Operator bridge: tunnel + verify + OpenAPI patch | Binding Crowley to `0.0.0.0` |

---

## Bridge operator tooling (V3.9.13)

One-command path from local Crowley to a Custom GPT over HTTPS:

| Artifact | Purpose |
|----------|---------|
| `scripts/start_chatgpt_bridge.sh` | Load `.env`, ensure bus, start Cloudflare quick/named tunnel or ngrok, patch OpenAPI, verify Actions over HTTPS |
| `scripts/patch_openapi_chatgpt.py` | Write `openapi-chatgpt.deployed.json` with live tunnel URL |
| `scripts/verify_chatgpt_actions_https.py` | Local + HTTPS smoke test (`health`, `context`, `retrieve`, `writeback/parse`) |
| `cloudflared/config.yml.example` | Named tunnel template for stable hostname |
| `docs/CHATGPT_SETUP.md` | Custom GPT + tunnel setup walkthrough |

Crowley stays on `127.0.0.1:8765`. The tunnel forwards public HTTPS only. Quick tunnels use random `*.trycloudflare.com` URLs; production uses `--named` + `CLOUDFLARE_TUNNEL_HOSTNAME`.

## Success criteria (met)

1. Unauthorized Actions requests fail; wrong bearer fails; missing key returns config error  
2. Authorized health, context, retrieve, portable packet, and writeback parse succeed  
3. Writeback ingest uses `ingest_terminal_writeback()` — staged sparks only  
4. `GET /api/health` remains public without auth  
5. Bridge script verifies Actions routes over HTTPS after tunnel start  
6. Full regression suite green with `CROWLEY_TEST_MODE=1` (**338 tests**)

## Patch — OpenAPI schema (2026-07-03)

ChatGPT’s Actions editor rejects object schemas with only `additionalProperties` and no `properties`. Fixed in `openapi-chatgpt.json`:

- Added reusable `LooseObject` component for flexible JSON payloads
- Defined explicit `ContextBundle` properties matching `build_context_bundle()` output
- Regression: `tests/test_patch_openapi_chatgpt.py` — `test_chatgpt_openapi_object_schemas_define_properties`

Re-import **`openapi-chatgpt.deployed.json`** after patching the server URL (bridge script or `patch_openapi_chatgpt.py`).
