# Crowley V3.9.18 — Agent Retrieval Enforcement

**Status:** Shipped (2026-07-06)  
**Release:** `CROWLEY_VERSION = "3.9.18"`, `Crowley V3.9.18 Agent Retrieval Enforcement`  
**Tickets:** #131–#135

---

## 1. Purpose

V3.9.17 added agent behavior instructions and validation. V3.9.18 **enforces** retrieval at the Actions gateway and persists handoffs as durable ticket records.

---

## 2. Handoff → ticket bridge (#131)

- `handoff_ticket_bridge.py` — idempotent `persist_handoff_as_ticket()` via `linked_memory_id`
- Wired into `ingest_handoff()` for `builder_handoff` and `architect_handoff`
- Backfill: `scripts/backfill_handoff_tickets.py`
- Done tickets include summary, QA, files, and handoff provenance

---

## 3. Strict pre-response gating (#132)

- `check_pre_response_gate()` in `agent_behavior.py`
- Returns `428 context_not_ready` when `validate_retrieval_state.ready == false`
- Payload includes `retry_path` (sync → domain tools → handoff.list)
- Exempt: retrieval tools, `handoff.ingest`, `writeback.*`, `audit.rollback`

---

## 4. Deterministic domain triggers (#133)

- `check_domain_retrieval_gate()` blocks non-domain tools until required reads fire
- Returns `428 domain_retrieval_required` with `required_tools` and `intent`
- Intent classified from `query`/`q`/`intent` args on each Actions call

---

## 5. Proactive chaining (#134)

- `COMPLEX_QUERY_KEYWORDS` — audit, consistency, review system, system-wide, etc.
- `PROACTIVE_CHAIN_POLICY` — min chain depth 2; requires handoff feed + repo or memory reads
- Complex queries fail `ready` until multi-step retrieval completes

---

## 6. Structured observability (#135)

Log entries per Actions call:

| Field | Description |
|-------|-------------|
| `tool_called` | Tool name |
| `reason_for_call` | Query text or intent |
| `chain_depth` | Chained read depth (max 3) |
| `triggering_rule` | `sync`, `domain_trigger`, `chaining`, `pre_response_gate`, `manual` |

Exposed via `inspect.retrieval_observability` and `behavior_payload.observability_schema`.
