## Goal

Classify cognitive **retrieval** queries into one of four modes — `recall` | `decision` | `reflection` | `planning` — via a rules-first `interpret_query(q)` API. Wire the mode into `spark_retrieval` / `build_cognitive_context` as optional auto metadata and record it on the cognitive context **trace when `debug=1`**.

**Non-goals for T1:** applying lane filters, changing score weights, enforcing the 8–15 cap, chat/`build_prompt` wiring.

---

## Problem (current state)

| Area | Today |
|------|-------|
| Query mode | None — retrieval treats every `q` the same |
| Lane filter | Manual `?lane=` / `lanes=` only; no inference applied |
| Trace | Has `depth`, `lanes_used`, counts — **no `query_mode`** |
| Scoring | Single global `W_SPARK_*` profile (0.40/0.25/0.15/0.20) |
| Depth caps | Medium can return up to 32 sparks (core+supporting) |

V4.2 shipped ingest intelligence (`cognitive_intent.py`). V4.3 starts the **read-path** twin.

---

## Design principles

1. **Rules-first** — keyword / phrase heuristics classify without a model; `CROWLEY_TEST_MODE` never calls a model.
2. **Optional light model only on ties** — deferred stub/hook; T1 ships rules-only with a documented tie-break default (`recall`).
3. **Emit, don't enforce** — T1 may return `inferred_lanes: list[str]` as a **hint**; T2 applies filter-before-score.
4. **Additive wiring** — existing `retrieve_sparks` / `build_cognitive_context` callers keep current ranking behavior.
5. **Do not remint V4.2** — no ingest/intent/chunking/promotion/extraction changes; preserve full acceptance matrix contract.

---

## Pipeline insertion

```
GET /api/cognitive/context?q=...&debug=1
  → build_cognitive_context(query, ...)
      → interpret_query(query)          ← NEW
      → retrieve_sparks(...)            (unchanged scoring/filter in T1)
      → trace.query_mode = mode         ← NEW when debug=1 (always record on trace)
      → trace.query_hints = hints       ← NEW (optional, debug)
```

`retrieve_sparks` may accept an optional `query_mode` / precomputed `QueryInterpretation` for forward compatibility with T3 profiles, but **must not** change weights in T1.

## New module: `cognitive_query.py`

```python
QueryMode = Literal["recall", "decision", "reflection", "planning"]

@dataclass(frozen=True)
class QueryInterpretation:
    mode: QueryMode
    confidence: float          # 0.0–1.0
    reason: str
    hints: dict[str, object]   # e.g. matched_markers, tie_break
    inferred_lanes: list[str]  # hint only in T1; may be empty

def interpret_query(q: str) -> QueryInterpretation: ...
```

### Mode keyword map (deterministic)

| Mode | Markers (examples) |
|------|--------------------|
| `planning` | `plan`, `roadmap`, `next steps`, `schedule`, `how should i`, `what should i do`, `prioritize`, `timeline` |
| `decision` | `should i`, `decide`, `choose`, `vs`, `or not`, `which option`, `tradeoff`, `commit to` |
| `reflection` | `how do i feel`, `reflect`, `looking back`, `what did i learn`, `pattern`, `why do i always` |
| `recall` | `what did`, `when did`, `remind me`, `what was`, `list`, `show me`, `do i have`, default fallback |

### Rule stack

| Order | Rule | Result |
|-------|------|--------|
| 1 | Empty / whitespace-only query | `recall`, low confidence, reason=`empty_query` |
| 2 | Count marker hits per mode (word-boundary / phrase contains) | Highest-scoring mode |
| 3 | Clear winner (score ≥ 1 and strictly greater than runners-up) | That mode, confidence from margin |
| 4 | Tie between modes | Default **`recall`**, reason=`tie_break_recall`; set `hints["tied_modes"]` |
| 5 | No markers | `recall`, reason=`default_recall` |

### `inferred_lanes` (hint only)

- Scan query tokens against `sparks.SPARK_LANES` + `sparks.DOMAIN_ALIASES` (e.g. `finance`→`money`, `career`→`work`).
- Return **sorted unique** lane list (0–N). Multi-lane allowed for cross-domain phrasing.
- **Do not** pass into `retrieve_sparks(lanes=...)` in T1 unless caller already supplied explicit lanes.
- Explicit `lanes` / `?lane=` continues to work exactly as today (caller-owned).

### Test mode

- `CROWLEY_TEST_MODE=1`: rules path only; assert no OpenAI/Ollama calls (patch guard in tests).
- Optional model tie-break: not invoked in T1 implementation (hook may exist as `None` / no-op).

## Caller wiring

### `context_orchestration.build_cognitive_context`

1. Call `interpretation = cognitive_query.interpret_query(query)` early.
2. Always attach to `trace`:
   - `query_mode`: interpretation.mode
   - `query_mode_confidence`: interpretation.confidence
   - `query_mode_reason`: interpretation.reason
3. When `debug=True`, also attach `query_hints` and `inferred_lanes` under `payload["debug"]` and/or `trace`.
4. Do **not** change core/supporting split, depth limits, or ranking.

Acceptance wording: “records query mode in trace when debug=1” — implement as **mode always on `trace`**, with richer hint dump under `debug` so non-debug clients stay lean if needed. Prefer always-on `trace.query_mode` (cheap, useful for T3/T5).

### `spark_retrieval.retrieve_sparks`

Optional additive kwargs (defaults preserve behavior):

```python
def retrieve_sparks(
    query: str,
    *,
    ...,
    query_mode: QueryMode | None = None,
    query_interpretation: QueryInterpretation | None = None,
) -> list[SparkRetrievalResult]:
```

- If neither provided, call `interpret_query(query)` once and stash mode on each result's score breakdown **only if** breakdown already exists and is additive — **or** leave scoring untouched and let orchestration own the trace.
- **Preferred T1 minimalism:** orchestration owns interpretation + trace; `retrieve_sparks` gains optional `query_mode` passthrough recorded in `score_breakdown["query_mode"]` when present, without weight changes.

### `GET /api/cognitive/context`

- No required new query params for T1.
- Optional additive `mode=` override (`recall|decision|reflection|planning`) if cheap: when set, skip auto-interpret and use explicit mode (confidence=1.0, reason=`explicit_mode`). If this expands API surface too much for T1, defer override to T3 and document as follow-up — **default plan: include explicit `mode=` override** (mirrors `lane=` pattern, tiny).

### Out of scope files

- `cognitive_intent.py`, ingest, chunking, promotion, extraction
- `memory_retrieval.py` / legacy `/api/retrieve`
- `build_prompt` / V4.4 chat wire
- Score weight tables / `COGNITIVE_DEPTH_LIMITS` (T3/T4)
