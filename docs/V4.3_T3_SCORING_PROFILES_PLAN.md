## Goal

Add **query-mode scoring profiles** so retrieval weights and soft boosts vary by `recall` | `decision` | `reflection` | `planning`, while the **recall profile preserves exact legacy** `0.40 / 0.25 / 0.15 / 0.20` hybrid scoring. Document profile + boosts in `score_breakdown`.

**Non-goals for T3:** retrieval caps (T4), V4.3 lock (T5), chat/`build_prompt`, tools-registry plumbing, V4.2 ingest, changing global `W_SPARK_*` without a profile wrapper, lane-filter redesign.

---

## Problem (current state)

| Area | Today |
|------|-------|
| Weights | Single global `W_SPARK_*` (0.40/0.25/0.15/0.20) for every query |
| Mode | `interpret_query` + `trace.query_mode` set; **mode never reaches `_score_spark`** |
| `retrieve_sparks` | No `query_mode` kwarg |
| Boosts | Certainty multipliers + secondary-lane 1.05; no trust / `spark_type` profile boosts |
| Trace `score_basis` | Hardcoded legacy formula string |

---

## Design principles

1. **Profile wrapper, not global mutation** — keep `W_SPARK_*` as recall/legacy constants; other modes use profile weight tables.
2. **Recall ≡ legacy** — fixed fixture scores must match current formula bit-for-bit (within existing `round(..., 4)`).
3. **Orchestration owns mode** — pass `query_mode=interpretation.mode` into `retrieve_sparks`; do not re-interpret inside retrieval.
4. **Direct callers default recall** — `retrieve_sparks(..., query_mode=None)` → `recall` (no auto-infer of mode).
5. **Additive breakdown** — always record profile name + weight set + boost multipliers.
6. **Stay in lane** — no caps, chat, tools contract, or V4.2 ingest edits.

```
build_cognitive_context(query, ...)
```

## 1. Scoring profile model (`spark_retrieval.py`)

```python
@dataclass(frozen=True)
class ScoringProfile:
    name: str  # recall|decision|reflection|planning
    w_semantic: float
    w_confidence: float
    w_recency: float
    w_graph: float
    # Soft multipliers (1.0 = no-op); applied after weighted base * certainty * secondary
    trust_active_boost: float = 1.0
    trust_stale_boost: float = 1.0
    spark_type_boosts: dict[str, float] = field(default_factory=dict)

SCORING_PROFILES: dict[str, ScoringProfile] = {...}

def resolve_scoring_profile(query_mode: str | None) -> ScoringProfile:
    mode = (query_mode or "recall").strip().lower()
    return SCORING_PROFILES.get(mode, SCORING_PROFILES["recall"])
```

### Proposed weights (sum = 1.0)

| Mode | semantic | confidence | recency | graph | Spirit |
|------|----------|------------|---------|-------|--------|
| **recall** | **0.40** | **0.25** | **0.15** | **0.20** | Exact legacy (`W_SPARK_*`) |
| **planning** | 0.30 | 0.20 | **0.30** | 0.20 | Recency up; semantic/confidence down |
| **decision** | 0.30 | **0.30** | 0.20 | 0.20 | Confidence up; mild recency |
| **reflection** | 0.25 | 0.25 | 0.15 | **0.35** | Graph reinforcement up |

Recall weights **must** be defined as aliases of `W_SPARK_*` so drift is impossible:

```python
SCORING_PROFILES["recall"] = ScoringProfile(
    name="recall",
    w_semantic=W_SPARK_SEMANTIC,
    w_confidence=W_SPARK_CONFIDENCE,
    w_recency=W_SPARK_RECENCY,
    w_graph=W_SPARK_GRAPH,
)
```

## 2. Boost stack (after weighted base)

Keep existing:

- `certainty_multiplier` (confirmed 1.00 > exploratory 0.92 > tentative 0.85)
- `secondary_lane_boost` (1.05 when intersecting filter; else 1.0)

Add profile soft boosts:

| Boost | recall | planning | decision | reflection |
|-------|--------|----------|----------|------------|
| Trust `active` / `pinned` | 1.0 | 1.05 | 1.05 | 1.05 |
| Trust `stale` / `rejected`* | 1.0 | 0.90 | 0.90 | 0.90 |
| `spark_type=decision` | 1.0 | **1.08** | 1.08 | 1.0 |
| `spark_type=intent` | 1.0 | 1.0 | 1.04 | 1.0 |
| `spark_type=observation` | 1.0 | 1.0 | 1.0 | 1.05 |

\*Rejected rows remain excluded from the candidate pool today; boost listed for completeness if stale/candidate appear.

Final score:

```
base = Σ w_i · component_i
final = round(base * certainty * secondary * trust_mult * type_mult, 4)
```

**Certainty already ranks confirmed > tentative at equal semantic** on recall; tests should still assert that under planning/decision profiles too.

## 4. Caller wiring

### `retrieve_sparks`

```python
def retrieve_sparks(
    query: str,
    *,
    ...,
    query_mode: str | None = None,
) -> list[SparkRetrievalResult]:
```

Pass `query_mode` into `_rank_spark_candidates` → `_score_spark`.

### `context_orchestration.build_cognitive_context`

```python
ranked = spark_retrieval.retrieve_sparks(
    ...,
    lanes=lane_filter,
    query_mode=interpretation.mode,
)
```

Update `trace["score_basis"]` to a short profile description, e.g.  
`"planning profile: 0.30 semantic + 0.20 confidence + 0.30 recency + 0.20 graph (+boosts)"`.

### Do not

- Auto-call `interpret_query` inside `retrieve_sparks`
- Change Actions/tool metadata beyond existing `query_mode` (already present)
- Change lane resolve / secondary filter semantics from T2
